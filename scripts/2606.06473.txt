Introducing MLEvolve, a groundbreaking self-evolving framework for Automated Machine Learning algorithm discovery, truly a game-changer in how we approach building machine learning systems. The paper introduces MLEvolve, which directly tackles the challenges of information isolation, lack of memory, and absence of hierarchical control in current machine learning engineering. It proposes a new method that combines progressive graph-based search, retrospective memory, and adaptive code generation to discover efficient algorithms across long time horizons.

MLEvolve's core brilliance lies in its Progressive Monte Carlo Graph Search, designed to remedy the inter-branch information isolation prevalent in traditional tree searches. It introduces cross-branch information sharing and a progressive exploration schedule, steering searches from broad exploration to focused exploitation. This approach achieves state-of-the-art performance with a notable 65.3% average medal rate under a limited 12-hour benchmark runtime on MLE-Bench, cutting the standard runtime in half. Moreover, it surpasses specialized methods like AlphaEvolve in algorithm optimization tasks, demonstrating both efficiency and strong cross-domain generalization.

One standout feature of MLEvolve is its Retrospective Memory system. This system blends a static domain knowledge base for initial cold-starts with a dynamic global memory that grows with each search iteration. It allows the agents to learn from both historical successes and failures without the overhead of constant calls to additional language models. Coupled with this is the Hierarchical Planning and Adaptive Code Generation strategy, which separates strategic planning from code generation. This enables MLEvolve to implement full rewrites, module-by-module edits, or diff-based changes, adjusting its approach dynamically according to the task requirements – a unique stratagem for iterative self-improvement.

However, it's worth noting that while MLEvolve shines in its expansive search and memory capabilities, its performance still anchors on the complexity of tasks. The necessity for substantial computational resources might be a limiting factor for smaller-scale applications.
